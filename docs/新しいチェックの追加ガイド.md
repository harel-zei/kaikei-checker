# 新しいチェックの追加ガイド

「こういう仕訳を見つけて指摘したい」というアイデアを、チェック機能として追加するための手順です。
**コードに詳しくなくても、この手順を Claude に見せながら頼めば追加できます。**

---

## 全体像：チェックは「4つの部品」でできています

1. **仕訳データ（`df`）** … アップロードされた仕訳が表になったもの
2. **チェッカー関数** … `df` を見て、あやしい行を見つける関数（`backend/checkers/` 配下）
3. **指摘（issue）** … 見つけた内容を表す1件の情報（勘定科目・日付・メッセージなど）
4. **登録** … `backend/main.py` にチェッカーを1行登録すると、実際に動く

追加作業は「チェッカー関数を書く」→「登録する」→「合成データで確認する」の3ステップです。

---

## ステップ1：やりたいことを言葉にする

まず、追加したいチェックを次の型で整理します（Claude に渡すとスムーズです）。

- **対象**：どの勘定科目・条件の仕訳を見たいか
  （例：「交際費」で「1件5万円以上」）
- **判定**：どういう時に指摘するか
  （例：金額がしきい値以上のとき）
- **レベル**：`error`（要修正）／`warning`（要確認）／`info`（参考）のどれか
- **メッセージ**：担当者に何と伝えるか
  （例：「交際費に高額計上があります。内容をご確認ください」）

> 💡 コツ：最初は「1条件・1メッセージ」の小さなチェックから始めると失敗しにくいです。

---

## ステップ2：雛形をコピーしてチェッカーを作る

雛形ファイルがあります：**`backend/checkers/_template_checker.py`**

1. これをコピーして、分かりやすい名前で保存する
   （例：`backend/checkers/entertainment_checker.py`）
2. 関数名を変える（例：`check_template` → `check_entertainment`）
3. 先頭の設定値（対象科目・しきい値）と判定条件を、やりたい内容に書き換える

Claude への頼み方の例：
> 「`_template_checker.py` を雛形に、交際費で1件5万円以上を『要確認』で指摘するチェッカーを
> `entertainment_checker.py` として作って。メッセージは日本語で。」

### 指摘（issue）の形（この形に合わせます）
```python
{
    "level":    "warning",              # error / warning / info
    "category": "T-1 交際費チェック",   # 画面での分類名
    "check_id": "T-1",                  # 重複しないチェック番号
    "account":  "交際費",               # 関係する勘定科目
    "month":    "2026-05-10",           # 日付（date_safe(row)）
    "slip":     "123",                  # 伝票番号（slip_safe(row)）
    "message":  "【T-1・中】…ご確認ください。",  # 担当者が読む説明
}
```

### `df` で使える主な列
| 列名 | 意味 |
|---|---|
| `date` | 日付（月は `df["date"].dt.to_period("M")`） |
| `debit_account` / `credit_account` | 借方／貸方の勘定科目 |
| `debit_sub` / `credit_sub` | 借方／貸方の補助科目 |
| `debit_amount` / `credit_amount` | 借方／貸方の金額（数値） |
| `debit_tax` / `credit_tax` | 借方／貸方の税区分 |
| `description` | 摘要（メモ） |
| `slip_no` | 伝票番号 |

## ステップ3：チェッカーを登録する（`backend/main.py`）

作ったチェッカーを2か所に足すと動きます。

**① ファイル上部の import に追加**
```python
from checkers.entertainment_checker import check_entertainment
```

**② `_checker_jobs` リストに1行追加**（`_run_checks` 関数の中にあります）
```python
_checker_jobs = [
    ("網羅性",       lambda: check_completeness(df_checked, fiscal_cutoff_day)),
    ("消費税詳細",   lambda: check_tax_detail(df_checked)),
    ("資産・修繕費", lambda: check_assets(df_checked)),
    ("債権債務",     lambda: check_ar_ap(df_checked)),
    ("ガバナンス",   lambda: check_governance(df_checked)),
    ("交際費",       lambda: check_entertainment(df_checked)),   # ← この1行を追加
]
```

> ここに入れると、「除外科目」や「対象期間」がすでに反映された `df_checked` で
> 自動的に呼ばれます。1つのチェッカーがエラーになっても、他のチェックは止まりません。

## ステップ4：テストを書いて確認する（実データは使わない）

⚠️ **顧問先の実データは使わず、ダミーの仕訳で確認**してください。

`tests/test_checkers.py` に既存チェッカーのテストが揃っています。同じ形式で
新チェッカーのテストを追加すると、以後ずっと自動で守られます。

Claude への頼み方の例：
> 「`check_entertainment` のテストを `tests/test_checkers.py` の流儀で書いて。
> 交際費6万円で指摘が出るケースと、4万円で指摘が出ないケースの両方。」

実行は `pytest` 一発です（全テスト数秒）。確認したいこと：
- 指摘してほしい行が、ちゃんと指摘される
- 指摘してほしくない行は、指摘されない（＝誤検知していない）
- **既存のテストも全て緑のまま**（他のチェックを壊していない）

なお、全体回帰テスト（`tests/test_regression.py`）の「ゴールデン件数」が
新チェックの追加で変わった場合は、内容を確認のうえ期待値を更新してください。

## よくある質問

**Q. プログラムが全く分かりません。それでも追加できますか？**
A. できます。ステップ1（やりたいことの整理）だけ日本語で用意し、あとは
このガイドと雛形ファイルを Claude に見せて「この通り追加して」と頼めば進みます。
最後の確認とレビューだけ、チームで一緒に行いましょう。

**Q. 既存のチェックを少し直したいだけです。**
A. 対象のチェッカー（例：`asset_checker.py`）を開いて、しきい値や条件、
メッセージを変更します。**変更後は必ず「結果が意図どおりに変わったか」を確認**してください。

**Q. チェック番号（check_id）は何番にすればいい？**
A. 既存と重複しない番号にします。カテゴリごとに `3-1`, `3-2` のように付いているので、
新カテゴリなら頭文字＋連番（例：交際費なら `E-1`）のように決めて、チームで共有しましょう。

## 参考：現在のチェック一覧（カテゴリ）

| カテゴリ | 内容 | ファイル |
|---|---|---|
| 1 | 網羅性・期間帰属・部門推移 | `completeness_checker.py` |
| 2 | 消費税区分の正確性 | `tax_detail_checker.py` |
| 3 | 資産・修繕費の判定 | `asset_checker.py` |
| 4 | 債権・債務の消込・滞留 | `ar_ap_checker.py` |
| 5 | 税務リスク・ガバナンス | `governance_checker.py` |
| 6 | 損益推移による定期取引の欠落 | `trend_checker.py` |
| 7 | 経過勘定の消込整合 | `reconciliation_checker.py` |

### カテゴリ6・7の使い分け（欠落・差額を見つける観点）

同じ「漏れ」でも、気づける切り口が違います。

- **6-1 科目レベル**：科目そのものが、ある月に丸ごと無い
- **6-2 補助科目レベル**：科目はあるが、特定の取引先・契約だけ無い
- **6-3 摘要レベル**：補助科目が無くても、摘要から同じ定期取引を識別して欠落を検知
  （例：新聞図書費に書籍代が毎月あるため、日経電子版の欠落だけを科目単位では拾えない）
- **6-4 途絶**：期の途中まで毎月あった取引が、以降ずっと計上されていない（解約か漏れかの確認）
- **7-1 未清算差額**：毎月計上・精算される経過勘定に、月額では説明できない端数が残っている
  （期首残高が無くても、当期の計上と精算の差から判定できる）
- **7-2 科目取り違え**：異なる科目に同額の未清算端数が残っている
