# 自動デプロイの設定

## なぜ手作業が必要だったか

Render（旧環境）はGitHubと連携していて、pushすると自動でデプロイされていました。
ConoHaは「素のサーバー」なので、その仕組みが最初から付いていません。
そのため、更新のたびに手作業で `git pull` と再起動が必要になっていました。

このドキュメントの仕組みを入れると、**pushするだけで自動反映**されます。

## 導入（サーバーで1回だけ）

```bash
git config --global --add safe.directory /opt/kaikei
cd /opt/kaikei
git fetch origin deploy/render-5yr4fy
git reset --hard origin/deploy/render-5yr4fy
bash deploy/install_auto_update.sh
```

最後に `✅ 自動更新を有効化しました` と出れば完了です。

## 動作

1分ごとにGitHubを確認し、更新があれば取得してサービスを再起動します。

安全対策として、取得後に次の順で確認し、**どれか1つでも失敗したら自動で元のバージョンに戻します**。

1. `requirements.txt` が変わっていればライブラリを更新
2. アプリが起動できるか（`import main`）
3. テストが通るか（pytestが入っている場合）
4. 再起動後にサービスが `active` になるか

壊れたコードが本番に残ったままになることはありません。

## よく使うコマンド

| やりたいこと | コマンド |
|---|---|
| 更新履歴を見る | `tail -30 /var/log/kaikei-update.log` |
| 今すぐ反映する | `sudo /usr/local/bin/kaikei-update` |
| タイマーの状態を見る | `systemctl list-timers kaikei-update` |
| 自動更新を止める | `sudo systemctl disable --now kaikei-update.timer` |
| 自動更新を再開する | `sudo systemctl enable --now kaikei-update.timer` |

## 注意

- 更新は **GitHubの内容で上書き**（`git reset --hard`）します。サーバー上で直接ファイルを
  編集しても次の更新で消えます。設定は `/etc/harel/kaikei.env` に書いてください
  （このファイルはリポジトリ外なので上書きされません）。
- 切り替え直前の状態は `backup-before-update` ブランチに残ります。
- 対象ブランチを変えるときは `/etc/systemd/system/kaikei-update.service` の
  `KAIKEI_BRANCH` を書き換えて `systemctl daemon-reload` してください。

## さらに速くしたい場合

1分間隔でも十分ですが、「pushした瞬間に反映」にすることもできます。
GitHub Actions からサーバーへSSHする方式で、GitHubのSecretsにサーバーの
SSH秘密鍵を登録する必要があります。鍵をGitHubに預けたくない場合は、
このタイマー方式のままにしてください（間隔は `KAIKEI_INTERVAL` で変更できます）。
