# サーバー引っ越し時のチェックリスト（Render → ConoHa 等）

サーバーを移設すると、**コードは動いてもfreee連携や前期データが引き継がれない**ことがあります。
これは不具合ではなく、それらが「サーバーの設定」と「外部サービス側の登録」に依存しているためです。

引っ越し時は以下を順に確認してください。

---

## なぜ引き継がれないのか（3つの要因）

| 要因 | 内容 |
|---|---|
| ① 環境変数 | `FREEE_CLIENT_ID` 等は Render の管理画面に登録されていたもので、**コードには含まれていない**（機密情報のため）。新サーバーに再設定が必要 |
| ② コールバックURL | freee側のアプリ設定に登録した `https://旧ドメイン/api/freee/callback` は、新ドメインでは無効。**freee側と新サーバー側の両方**を更新する必要がある |
| ③ 保存データ | 前期データ・freeeトークンは Supabase に保存していた。Supabaseを使わない設定にすると**過去のデータが読めなくなる**（＝要・再連携／再アップロード） |

---

## 手順1: 環境変数を新サーバーに設定する

リポジトリ直下に `.env` を作成します（雛形は `.env.example`）。

```bash
cd /path/to/kaikei-checker
cp .env.example .env
vi .env     # 値を設定
```

**最低限、以下を設定してください。**

| 変数 | 設定する値 |
|---|---|
| `APP_USERNAME` / `APP_PASSWORD` | ログイン用（旧環境と同じ値にすると利用者が混乱しません） |
| `FREEE_CLIENT_ID` / `FREEE_CLIENT_SECRET` | freeeアプリ管理画面の値（旧環境と同じ） |
| `FREEE_REDIRECT_URI` | **新ドメイン**の `https://新ドメイン/api/freee/callback` |
| `SUPABASE_URL` / `SUPABASE_SECRET_KEY` | Supabaseを**継続する場合のみ**設定（下記「手順4」参照） |
| `ANTHROPIC_API_KEY` | AI選別を使う場合 |

> systemd で常駐させている場合は `.env` ではなく
> ユニットファイルの `EnvironmentFile=/path/to/.env` を指定する方法でも構いません。

## 手順2: freee側のコールバックURLを更新する

1. [freeeアプリストア](https://app.secure.freee.co.jp/developers/applications) にログイン
2. 対象アプリの「アプリ管理」→「基本情報」を開く
3. **コールバックURL** を新ドメインに変更
   ```
   https://新ドメイン/api/freee/callback
   ```
4. 保存

> ⚠️ `.env` の `FREEE_REDIRECT_URI` と**1文字も違わない**ようにしてください。
> 末尾スラッシュの有無、http/https の違いでも認可が弾かれます（`redirect_uri_mismatch`）。
> また freee は本番環境で **https 必須**です。ConoHa等では独自ドメイン＋SSL証明書
> （Let's Encrypt等）の設定が前提になります。IPアドレス直打ちでは登録できません。

## 手順3: 再起動して確認する

```bash
# アプリを再起動（systemdの例）
sudo systemctl restart kaikei-checker
```

**確認方法：** 画面のSTEP2に「🔗 freeeから取得」タブが表示されれば設定成功です。
表示されない場合は環境変数が読めていません（手順1を再確認）。

## 手順4: 保存データの方針を決める

前期データ（前期仕訳帳・期首残高）と freeeトークンの保存先を決めます。

### 案A: Supabaseを継続する（最も手間が少ない）

`.env` に `SUPABASE_URL` と `SUPABASE_SECRET_KEY` を旧環境と同じ値で設定するだけです。
**保存済みの前期データも、freee連携も、そのまま引き継がれます。**

### 案B: サーバー内保存に切り替える（Supabaseをやめる）

`SUPABASE_URL` / `SUPABASE_SECRET_KEY` を**空**にすると、
`backend/client_data/` 配下に保存されます。
ConoHa等のVPSは永続ディスクがあるため、この方式でも消えません。

ただし移行作業が必要です：
- **前期データ**: 各クライアントの前期ファイルを画面から再アップロード
  （またはSupabaseからダウンロードして `backend/client_data/<クライアント名>/` に配置）
- **freee連携**: 画面から事業所ごとに再連携（手順5）

> ⚠️ `backend/client_data/` は顧問先の個人情報を含みます。
> `.gitignore` で除外済みですが、**バックアップの取得**と
> **サーバーのアクセス制限**を必ず行ってください。

## 手順5: freeeを再連携する（案Bの場合、または連携が切れている場合）

1. 画面のSTEP2で「🔗 freeeから取得」タブを開く
2. 「freeeと連携する」をクリック
3. freeeの認可画面で**対象の事業所を選んで**許可
4. 顧問先が複数ある場合は「＋ 事業所を追加連携」で1社ずつ繰り返す

---

## トラブル時の切り分け

| 症状 | 原因と対処 |
|---|---|
| 「freeeから取得」タブが出ない | 環境変数（CLIENT_ID / SECRET / REDIRECT_URI）のいずれかが未設定。3つ揃って初めて表示されます |
| 連携ボタンを押すとfreeeでエラー | コールバックURLの不一致。手順2を確認（httpsか、末尾は `/api/freee/callback` か） |
| 連携済みなのに「この事業所は連携されていません」 | その事業所のトークンが無い状態。「＋ 事業所を追加連携」でその事業所を選んで認可 |
| 以前の前期データが消えている | Supabaseから切り替えた影響。手順4を参照 |
| 仕訳帳取得がタイムアウト | freee側の生成に時間がかかっています。件数が多い場合は期間を区切って再実行 |

---

## 引っ越し前に控えておくべき情報

次回の移設に備え、以下を記録しておくことをお勧めします。

- [ ] freee の Client ID / Client Secret
- [ ] Supabase の URL / Secret Key / バケット名
- [ ] Anthropic API キー
- [ ] ログイン用のユーザー名・パスワード
- [ ] 旧環境のコールバックURL（新旧の対応がわかるように）
